## 请网站侧先完成的方案 / 契约

1. **图片隐私与内容安全**：明确实际采用的处理机制、执行时点、拒绝/未完成/失败返回、图片及结果保留/删除边界、是否向外部服务送图及实际平台声明。保持用户取消/拒绝时仍能手动选图。图片解码、识别成功和成绩审批均不算安全审核；不因“仅私有游戏截图”直接改成private_unmoderated试跑。若需新增安全处理状态/错误，先固定协议及测试用例回交，不能让小程序猜字段。未确定前公网OCR继续关闭。
2. **单一执行队列**：明确隔离访客网关如何安全复用现有唯一RecognitionService / JobStore / worker、可信IP配额和全局容量，并维持会话owner隔离。第一阶段轻量进程没有该桥接，不另启动第二套模型或绕开生产监督者；网站侧先提供可评审架构、资源与Linux隔离测试证据，需要现场操作时另按用户授权逐步执行。不能让小程序直接转发网页Cookie接口，也不能把正式账号库挂给隔离访客。
3. **固定路由与能力**：沿 `MINI_API_CONTRACT_20261102.md`。除保留session/snapshot外，OCR需catalog、jobs上传、jobs/by-request恢复及jobs/{id}查询/取消；精确method/query规则由原协议约束。GET jobs路径仍带server/catalog_version，上传query带server/catalog_version/request_key，multipart只收一份image。账号/B–E保持关闭。CN仅在实际可用且获准后提供map_recognition=true及64位catalog_version；Global继续false/null。目录/快照与identity必须一致。
4. **HTTPS上传边界**：由运维给出确定的HTTPS origin及精确Nginx路由、单图8MiB/封装额外64KiB、16M像素、限流和读取/队列/运行截止配置；保持Cookie/Origin拒绝、可信Host/IP、no-store及原网站预算。当前session的4KiB限制不能套用于图片，也不能泛化放宽所有路由。现场执行前先核对版本/队列/资源，按用户既有方式一次一个只读步骤，不提供批量生产写脚本。
5. **可回退与保全**：固定新源码/原生契约/数据来源/配置范围及验收回执；保护现有访客状态和原网站/正式双服指针，不清旧会话续期、不复制业务库，不修改维护工作簿。关闭OCR后继续提供手选和快照；保留必要证据，不把旧正式账号库/score-state恢复成测试种子。

上述公共后端、内容安全或配置模板改动由网站分支归口；本分支只负责原生UI、request/media/storage/lifecycle。现有固定协议已足够的字段不另发明第二套。
