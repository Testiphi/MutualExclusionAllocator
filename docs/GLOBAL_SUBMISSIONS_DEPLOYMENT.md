# 双服投稿与国际成绩状态升级

本文件用于后续经用户授权的云端升级。本地开发完成不代表已构包、Linux原生通过或生产已验收。以最终发布回执固定源码提交、批准数据来源、发布ID和归档SHA。

## 兼容影响与发布范围

- coverage schema2：新增国际选图表，保留国服选择、原事件和旧账号/投稿/账本。
- 国际成绩组件schema1：独立 `global-score-state` 和 `global_score_current/global_score_batches/global_score_control`；不覆盖国服 `score-state`。
- 国际首阶段仍仅五区满星理论；维护四区/高手、工作簿、独立参考和台账不进入运行。国际投稿审核不自动应用；应用/回滚需超级管理员密码重验和逐项确认。
- 共用积分与门槛，一级两服各选一图，二级解锁两服；缺少服别的历史记录仍为国服，原目标键不重算。
- 新应用、成套备份/恢复工具和能力清单必须一起升级。没有新增依赖、Nginx、systemd或环境变量要求；仍须核对现有API转发、CSRF/Origin和限流。

## 前置核验与执行顺序

1. 只读确认current与真实进程cwd、主schema和所有组件、正式国服版本、国际当前三件套版本/哈希、未完成应用批次、Nginx配置、磁盘、备份timer和最近真实备份/恢复。
2. 固定首次国际种子及其来源，只允许用户批准的运行三件套。未来已有国际运行状态时不能用代码包重播种；维护侧新成绩需单独做相对于活动版本的受控差异。
3. 校验完整发布归档和逐文件清单，暂存新版本；使用目标Linux原生Python和锁定离线依赖运行临时库自检。Windows或夹具测试不能替代该步骤。
4. 在线成套备份、校验和独立恢复演练；暂停原timer并确认备份服务结束，停应用确认MainPID0，再做停服最终成套备份/恢复点。
5. 从新版本工具执行coverage只读preflight，带现场国服版本执行显式migrate，仅0/1→2，不能重跑旧组件迁移。新应用不会自动迁移正式库，也不能在coverage2而国际状态未初始化时启动。
6. 执行国际状态只读核验：

```text
.venv/bin/python -B -m backend.global_score_production preflight --config /etc/racepick/production.json
```

国际状态尚未初始化且两服均无未完成批次时，按已核对的版本执行：

```text
.venv/bin/python -B -m backend.global_score_production migrate --config /etc/racepick/production.json --source <批准三件套目录> --expected-dataset <批准国际dataset_version> --expected-cn-version <现场国服版本>
```

工具校验国际完整字节/身份/规则/范围，绑定当前账号库，保留已有业务行。国际写回默认关闭；重复调用不会重播种或覆盖后续投稿成绩。初始化失败保留种子/日志，部分表和不同种子均需停止核对，不删表或目录来绕过门禁。

7. 用新版工具完成迁移后成套备份、校验和独立恢复演练，归档须同时包含账号库、国服版本、国际三件套版本/批次备份、覆盖表选择/事件和统计。不得把单独数据库副本作为完整恢复点。
8. 按用户授权、在原国服总写回开关状态明确后决定是否启用国际写回：

```text
.venv/bin/python -B -m backend.global_score_production enable --config /etc/racepick/production.json
```

国际写回同时受原写回总开关约束，不顺带改变国服开关。关闭命令为同工具 `disable`。不为验收刷假积分、假投稿或导入测试账号。

9. 兼容门禁通过后激活并核对current/PIDcwd、coverage2/global-score1和原组件，确认国服版本/规则保持、国际版本来自批准种子。核验原子快照、双服计算、分服本机车库、投稿/证据/审核、应用回滚权限、两服独立选图与真实账本降级行为；手机微信由用户实际验收。
10. 新应用上线后的成套备份、恢复演练和一次真实备份服务成功后，恢复timer并检查真实执行结果与下一次计划。未来计划不记作已成功。

## 停止与回退

版本漂移、部分表、原业务行变化、未完成批次、备份/恢复/权限/锁/兼容异常均停止并保留现场。coverage2与国际状态启用后，旧应用/旧备份工具不兼容，禁止只切旧链接或绕过能力门禁。优先兼容修复；整套恢复需单独授权，并先保全升级后的新增数据。

应用内成绩回滚只改变对应服别版本和该批次回执/奖励，不恢复旧账号数据库；存在后续版本时不能覆盖回滚。成套灾难恢复必须同时处理账号库、两服状态和其他已声明组件，不允许只恢复其中一服或覆盖包内JSON。
