# 网页镜像范围与实现路径待核实

2026-11-03。用户最新明确：除平台不可行或移植代价极大外，网页全部外观和功能均应镜像到小程序；以网页为唯一产品基准，不另行设计两套产品。此要求取代原“首版仅四项”的范围限制，但不授权生产/微信后台/上传/发布，也不改变公共源码/后端由网站分支归口、依赖交用户协调的分工。

## 实现路径的真实约束

原生WXML/WXSS不能直接执行既有HTML/DOM。要完全使用同一份页面，web-view最直接；2026-11-03只读核对官方 `https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html`，正文明确“个人类型的小程序暂不支持使用”，其他网页须配置业务域名。网页工具打开失败后直接读取同一官方URL核对；未操作后台或假定主体权限。

已向用户询问主体类型，等待答复。未擅自把当前原生项目换成web-view，也未因该约束删除用户要求的功能：

- 若主体具备web-view权限：优先评估复用**同一份网页和现有后端**，仍需用户协调业务域名/TLS、登录/存储/相册能力与真机平台行为；不把开发工具跳过域名校验当真实可发布权限。仅相册不显示拍摄的要求也必须保留，若网页文件选择器做不到，明确具体平台差异及必要桥接。
- 若主体为个人或无web-view权限：原生层只承担平台控件/生命周期/网络适配；共享页面状态/规则/数据/接口由网站归口，建立逐项对照与共同的UI规范，不能继续自由设计外观或复制第二套业务算法。完整账号、投稿和管理功能需要网站补充经过授权的原生认证/角色接口；当前访客token不能取得网页用户或管理权限。

## 执行标准

1. 外观直接参考现有手机网页：背景、颜色、按钮、标签、间距和布局，不再以“规整”之名改成另一种设计。
2. 功能按同角色/同开关/同数据/同输入逐项对照；页面存在不等于接口可用，不用mock充当已迁移。
3. 先确定主体/复用路径，再由用户协调必要网站公共层或认证接口。后续跨分支需求列路径、固定提交、请求/响应、角色兼容和验收用例，不同时抢写。
4. 当前原生识图阶段验收与“全网站镜像完成”是不同事实。本轮不会把前者写成后者；真机、真实微信平台鉴权、域名/隐私/图片安全与审核仍待实际验收。
