# 网站跑法参考发布说明

发布包包含双服 957 条启用绑定的 JSON 种子。账号、会话和原有停用记录不作为种子。网站只有在现有版本化账号库已显式初始化跑法表后才提供跑法参考入口。现有的管理员角色、会话及 CSRF 检查仍用于维护操作。

先核对现场 current、服务实际目录、国服和国际服活动版本、成绩待处理批次、账号库与备份状态。按网站部署说明验证离线依赖、目标 Linux 自检、当前路由和已有正式 A/OCR 门禁。跑法接口通过网站现有 API 路由提供。先确认该路由覆盖 `/api/route-videos`，以及网站服务用户仍能读写既有账号库。

以实际网站配置，在暂存版本目录运行只读预览：

```sh
python -m backend.route_video_release --config /etc/racepick/production.json --expect-sha256 9f1180eb11f747112de97041cbd487ac9b3cd8bbcc115a5aa703e44e39d0a9a5
```

检查新增、重复和冲突。另获现场授权后，停网站服务，在实际服务身份下加 `--apply`。工具持服务锁，先创建现有双服成套备份，再以事务只新增缺失的绑定，保留同键冲突和停用状态。初始化创建两张独立跑法表，归入账号 SQLite，随既有成套备份。应用启动只核对版本标记，启动时不会自动导入种子。先在独立恢复目录完成备份恢复演练，再启动并核对矩阵、逐项样本以及原账号和成绩指针。

包内成绩是可校验的发布种子。现有网站活动成绩从独立版本指针读取。需要把五条变化投入活动成绩时，以当前真实版本为基线另做定点计划和备份验证。现场差异若超过这五条和一条普通档镜像，应停下来审查数据版本差异。

应用回退前复核旧应用兼容当前成绩和 OCR schema。旧应用不读取跑法表，表可保留供再次启用。若新增表和备份恢复验证有异常，应停服定位。任何实际数据恢复需先核对后续业务写入，避免覆盖新会话、账号或投稿。

## 既有绑定的专用更新入口

`python -m backend.route_video_update` 使用 `--baseline`、`--candidate`、`--plan` 和 `--expect-plan-sha256` 固定输入。工具先核对三个文件的哈希及逐键差异。默认只读预检，冲突返回退出码 2。已有目标行必须启用，且全部可变字段等于基线值或目标值。新增键须缺席或已启用且与目标完全一致。

本地预检通过 `--isolated-db` 指定隔离数据库。显式写入须追加 `--apply --isolated-backup <新文件路径>`。工具备份后在同一事务中重新预检、更新既有行、插入新增行并读回复核。生产 `--config` 入口沿用维护锁和成套备份流程，仍待目标 Linux 验证。

Windows 隔离 SQLite 使用 957 条基线和本地确认的 974 条候选实测。只读预检报告 412 条更新、17 条新增和零冲突，数据库哈希一致。写入后 974 条逐键匹配，原行 ID、启用状态、分 P、起播点及无关记录保留。新增阶段注入失败后整批回滚，停用冲突阻止写入，独立备份可恢复。重复执行零更新、零新增，数据库哈希一致且没有创建额外备份。确认版种子、逐项计划和机器回执随本地待发布资料保管。
