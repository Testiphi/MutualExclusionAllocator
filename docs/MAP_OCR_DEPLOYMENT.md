## 应用包之外的配套配置

默认OCR关闭；生产入口只在显式设置 `RACEPICK_MAP_RECOGNITION_CONFIG` 后接入。已有业务 `/etc/racepick/production.json` 四字段格式保持，SMTP凭据不混入识图配置。

状态目录模板 `/var/lib/racepick/map-recognition` 必须是**实际账号data_dir下同名独立子目录**，目录/配置0700/0600，属主与服务一致；若现场账号路径不同，先调整模板并核验，不照抄。包和模型只读，状态不放在release/current中。

新 `racepick-map-ocr.service` 是唯一worker监督者；API不启动/停止worker。初始模板用户racepick、UMask0077、无网络、只对独立队列目录可写；通过私有临时挂载隐藏其他 `/var/lib/racepick` 内容，再单独绑定队列。MemoryHigh768M/MemoryMax1G/禁止swap、CPUQuota100%、TasksMax64、KillModecontrol-group。**这是待现场容量核验的初始上限，不能凭本地机器推断生产容量。** systemd沙箱在现场启动后还须核验实际路径/权限/内存和进程回收。

监督者每0.5秒巡检：模型启动120秒；单次执行45秒（取消后也保留硬截止）；队列等待120秒；滚动5分钟最多3次启动，超出先冷却；退出/超时仅终止自己持有的子进程，失败任务不自动重放。异常时API返回不可用，原手动选图保持。调用者须取消或重试，不能发布迟到结果。

上传原始PNG/JPEG/WebP≤8MiB、≤1600万像素，完整横屏宽≥600/高≥300/比例1.30–2.20，实际MIME和解码校验；API在受限模型进程之前拒绝极端长图。每会话2个待处理、全局8个待处理、每会话及可信IP10分钟各20次提交；媒体128MiB、可用磁盘至少64MiB、最多10000条队列元数据/数据库页数限制。上述额度也受现场磁盘策略约束，不是全盘空间隔离证明。

图片及结果默认1小时到期，元数据另留10分钟用于明确到期语义，然后清除；只清理带队列标记目录中本服务拥有的任务及图片，不清理其他文件、原证据或备份。服务停机期间无清理，重启后继续；不承诺停机时仍准点到期。监督者日志写journal，无完整OCR原文、图片或令牌日志；按现场journal磁盘预算限制。队列与照片不加入长期业务备份；正式业务备份工具和原备份timer保持。

Nginx必须**成套更新http map/zone和HTTPS站点location**：现有3m默认大小保留；仅精确 `/api/map-recognition/jobs` 提至8m；识图单独 `racepick_map_requests` 桶6r/s/burst12，原业务5r/s/burst30、统计2r/s/burst10保持，识图不消耗这两桶。前端查询从1秒渐退至3秒，429等5秒再查，整体180秒后可重试查询，不重复上传。包体读取上限仍由API二次执行。保持证书、ACME、代理及可信客户端头，禁止直接暴露后端或新增公网worker端口。

2. 校验完整归档SHA、外层逐文件清单、内层manifest/CRC/来源；暂存全新release目录。通过 `production/install-runtime.sh`离线安装及业务临时库自检，再执行真实CPU `production/ocr-selfcheck.py`。这些只用临时库/合成图，不等于真实页面OCR或生产验收。
3. 在独立临时状态演练真实样例、会话/服别隔离、坏图/3–8MiB图/取消/超时/worker退出、8任务排队、磁盘与内存预算；记录p50/p95/峰值和API响应。测试图片由私有验证资料提供，不把测试图片放入发布包。
4. 按授权备份正式业务与配置，确认恢复点。只为OCR新建独立空目录，以实际服务用户执行新包 `.venv/bin/python -B -m backend.map_ocr_production provision --state-dir <独立目录>`。它不会初始化正式账号或成绩。已有目录则同用户用check，不覆盖。目录/配置必须属于运行用户，不把root拥有的目录直接交给racepick启动。不要重跑历史业务迁移。
5. 核对systemd模板路径/沙箱预算；先部署并启动唯一OCR服务，确认ready、无网络、权限、停止及重启回收。accounts单位新增可选EnvironmentFile；未设置时OCR保持关闭。准备 `/etc/racepick/map-recognition.env` 内容仅为 `RACEPICK_MAP_RECOGNITION_CONFIG=<已核验配置路径>`，关闭时移除该项。不要同时用demo脚本/Popen启动另一个worker。
6. 备份两份Nginx配置，成套编辑、`nginx -t`通过后才按授权reload。保留TLS及旧业务限流；验证真实>3MiB≤8MiB上传、>8MiB拒绝、非识图路径3m仍生效、限流429不会压住登录/成绩快照。
7. 最终经单独上线授权切换应用并启用OCR环境项；确认两服务实际cwd/新包与健康、两服活动成绩及开关不变、真实登录/游客识图与确认、成绩表标识、手机微信体验、故障时手动回退。没有真实事件的提醒继续待验证。
8. 新版备份/恢复演练按现有兼容流程核对；不得用识图测试制造生产投稿/积分，或将将来timer执行记为已完成。记录完整部署回执后交用户验收，不发公告或清理旧包。

## 回退

OCR启动/超时恢复失败、资源或磁盘超预算、业务被429影响、隔离失效、成绩/车库非预期改变或Nginx校验失败，停止推进。优先撤销OCR环境项并重启账号服务关闭入口，再停独立OCR服务；保全队列/日志。回退程序只选兼容coverage2/global-score1及全部现有组件的旧包；新业务数据不回滚，绝不用包内JSON覆盖score-state。恢复配套配置先校验再按授权reload。整套业务数据恢复需另行授权并保全新增。

当前版本不需要账号/成绩schema迁移，只需显式创建全新独立OCR队列。维护成绩的生产导入是另一项有审批边界的动作，不在代码激活或OCRprovision中执行。最终Linux验证和构包事实见随交付回执，现场systemd、生产容量、真实手机微信与生产验收仍由云端逐步核验。
