## 范围与交互

- 所有管理员（含超级管理员）：新投稿、补充重提 → 首页「管理工作台」→「投稿审核」→ 投稿页「审核工作台」→ 具体条目。
- 投稿人（包括管理员自己的投稿）：审核结果、要求补充、重开及质量评分/评语调整 →「数据贡献」→「我的投稿」→ 具体条目。
- 超级管理员：新问题反馈、用户补充 →「管理工作台」→「用户反馈」→「管理用户反馈」→ 具体条目。普通管理员不新增查看他人反馈的权限。
- 问题反馈提交人：站长回复/处理结果 →「个人中心」→「问题反馈」→「我的反馈」→ 具体条目。

未读不是待处理。每个账号独立保存已读位置；A已读不改变B，也不改变业务状态。待审核投稿被实际处理后从所有审核员的待审核提醒退出；未处理且仅被A阅读的投稿仍提醒B。用户反馈的「待处理 N」按反馈实际 `pending` 条目统计，不按消息条数或未读数统计。

初次启用前已有内容不回填通知，视为已读基线。新事件写入与原业务操作同一事务；不复制正文、邮箱或证据。自己的操作不提醒自己。仅进入目录/列表不标记已读；成功渲染具体详情后，以详情返回的事件游标POST确认，只覆盖已展示版本。后台新消息和旧窗口的迟到确认不会被误清除。读状态保存到账号库，刷新、重新登录、其他设备共享。

小圆点无闪烁、无数字，具有「有未读内容」无障碍标签。外层菜单和内部入口汇总同一状态。经用户选择，首页导航按钮、菜单卡片、列表条目均在右上角显示。样式预览 `examples/unread-marker-preview.html` 可切换文字右侧/右上角/左上角；模板中的数量是虚构示例。

页面可见时每60秒刷新；重新获得焦点、从后台返回及已读操作后刷新。隐藏页面暂停请求，不在隐藏时标记已读；网络失败保留最后状态，401/403或身份/角色变化清除旧账号标记并停止当前控制器。页面离开清除定时器。未自动重绘详情和输入表单，避免覆盖未提交内容。

## 验收步骤

1. 两个管理员分别登录，投稿人提交；两管理员的管理目录/投稿审核/队列均亮点。
2. A只打开列表，点保持；A打开具体详情，A点灭，B保持。状态仍待审核。
3. 审核要求补充，投稿人数据贡献/我的投稿亮点；打开详情消除。补充重提后两管理员再次亮点。
4. 玩家新建反馈，超级管理员管理目录及用户反馈亮点；普通管理员不出现反馈管理入口。阅读后点灭，待处理数保留。
5. 站长回复后，玩家个人中心/问题反馈/我的反馈亮点。用户再补充，站长重新亮点。
6. 验证新消息到达时旧详情的已读确认只清旧版本；刷新/重登保留；多窗口、窄屏和会话失效时不串账号、不覆盖草稿。

管理员反馈页原「全部反馈」仅重复刷新列表，按用户反馈隐藏该重复按钮；管理员反馈页不再显示页面级汇总未读点，仅列表条目提示；首页管理目录入口继续汇总。普通用户仍保留「新建反馈 / 我的反馈」切换。
