## 首版产品范围

建议首版采用**原生微信小程序 JavaScript/WXML/WXSS**，复用既有CommonJS业务核心和同一后端。只有一个目标平台，暂不整体迁移网页到跨端框架；不使用web-view套网页。构建过程自动将共享源码打包进小程序，不能长期维护两份人工复制的算法。

| 首版包含 | 行为与边界 |
|---|---|
| 手动选图 | 按顺序选择五张大/小地图，保持现有大地图唯一性与目录校验；改图不自动清空车库 |
| 车库选择 | 游客本机保存：搜索、选车/取消、星级与当前服别允许的OC等状态；明确保存/恢复，沿用网页语义；国服、国际服草稿隔离 |
| 计算结果 | 与网页相同的候选生成、互斥分配、成绩计算、方案排序与空缺语义；结果在当前页展示，可修改输入后重算 |
| 现有截图识别 | 相册选择一张游戏截图→本机预览→后端识别→五槽核对/补充→一次确认填入→复用计算；不增加独立上传导航页 |
| 服别 | 支持国服及国际服手动计算；国服保留已有区/档/星级规则，国际服按当前capabilities仅五区满星理论，普通与OC身份不混用 |
| 异常恢复 | 断网、缓存不足、目录更新、后台返回、识别失败均不丢原车库/已选地图；重新计算不被旧请求覆盖 |

首版**不包含**：英文界面OCR、国际服实图新增适配、拍屏照片/视频识别、小程序本机模型推理、面向用户的RacePick账号登录/邮箱绑定、云端账号车库同步、成绩投稿/审核、公开昵称/贡献榜、反馈附件、独立完整擂台成绩表、支付/订阅/推送。底层用wx.login临时代码建立小程序访客会话，不要求用户注册RacePick或提供昵称/头像/手机号。

国际服可手选计算，不等于首版承诺国际服截图识别准确率。识图按钮按已验收能力开放：先开放国服中文截图；国际服保留手选及明确的未开放状态，不能静默走国服目录或误填。若用户决定首版必须国际服识图，需另补真实样本验收，而非直接打开开关。

首版先做游客流程，用户无须登录即可计算。**网页账号和浏览器本机车库不会自动出现在小程序。** 小程序本机车库是独立数据；将来跨端同步应通过显式登录/账号绑定和冲突确认接入原内部user_id，不按昵称/邮箱字符串自动合并，不创建虚假权益或覆盖旧车库。本方案不引入账号库迁移。

## 页面与交互

首版一个主页面，避免反复跳转：

1. 顶部选择服别及该服可用区/档；切换前保存当前服别本机草稿，切换后恢复对应草稿。
2. 地图区提供五行手选，下方或同区提供简洁“地图识别”入口；只有“仅游戏截图、不支持拍屏”的必要说明。点击从相册选图，首版不主动提供拍照入口；选取机制无法证明图片一定是截图，因此界面说明不冒充自动拍屏检测。
3. 车库区默认可折叠，打开后在同页/底部面板搜索选车和改星级，不强制进入第二个页面。
4. 点击“生成方案”，结果直接显示在当前页下方。计算期间防重复发布旧结果；改图、改车、切服后使旧计算失效。
5. 识别结果在地图区内展示，可修正未识别项；用户点“应用选图”才替换原五行。取消/失败/退出不自动覆盖手选结果。

原网页擂台表入口和“新功能”标识继续保留；小程序V1不新增一个无法完整实现的空壳成绩表入口。实际新页面不陈列调试、验收、样例、格式/依赖/到期时间清单。

## 后端接入方案：先适配再复用

新增原生专用前缀（拟定 `/api/mini/v1`），默认关闭，先在独立测试环境验证。现有网页接口及Cookie/Origin/CSRF保持，不能只用来源头、Referer、AppID或客户端类型判断身份。

拟定协议：

| 请求 | 作用 |
|---|---|
| `POST /api/mini/v1/session` | 接收wx.login临时代码，服务端验证后签发短期、最低权限访客令牌，不注册正式RacePick账号、不取得贡献权益；限流/撤销/有效期独立明确 |
| `GET /api/mini/v1/snapshot?server=...` | 委托原两服原子快照，返回活动版本/原始字节哈希及相应目录与capabilities；目录异常不回退另一服 |
| `GET /api/mini/v1/map-recognition/catalog?server=...` | 委托同一活动目录与版本；原生会话归属校验 |
| `POST /api/mini/v1/map-recognition/jobs` | 接收原生文件上传，绑定令牌、服别、目录版本、request_key；转换到既有私有队列服务 |
| `GET/DELETE /api/mini/v1/map-recognition/jobs/{id}` | 复用查询、取消、超时和结果语义；只允许原匿名会话访问自己的任务 |

以上是设计接口名，不是现有可调用路由。实现时先抽取现有任务业务调用，网页和小程序入口共同调用；不复制两套JobStore或处理规则。

原生令牌只在内存持有，不放进URL、日志或共享核心；原生session创建需要服务端资源防护，不能因访客就无限签发/不限额。AppSecret/session_key只留服务端；平台标识与原生访客会话在独立状态中管理，不自动绑定网页user_id，隐私说明如实包含所需标识和用途。访客会话到期或小程序重启后先重新验证；仍无法访问旧任务时保留车库/地图草稿并给出重试入口，旧照片由既有到期策略收尾。具体结构/兼容影响在实施前列清，不接正式账号库自动迁移。

使用 `wx.uploadFile` 时是multipart，与网页raw-body上传不同。新增精确路由适配、先鉴权限额并受限流式读取；保留单图8MiB/16M像素及格式验证。multipart请求总大小要给有界封装余量（拟8MiB+64KiB），同时单文件仍≤8MiB；客户端字段数量、文件数和文件名都有限制，不扩大其他接口上限。Nginx新路由的请求大小/限流必须与后端成套匹配，不能直接套用网页原路径或把所有POST改为multipart。

原生入口按可信IP/会话与全局共享OCR资源额度；与网页共用worker容量，不能各放8个后突破全局限制。不同入口owner标识做命名空间隔离。识图结果继续固定五槽、版本/服别绑定、歧义留空且须用户确认；不回显与地图无关的OCR原文。

## 存储与数据一致性

- 车库、星级、OC、区档和五图选择按schema版本/服别保存，写入失败不覆盖旧值；恢复时按当前车辆目录过滤已失效身份，给出可恢复状态，不擅自补车或改规则。
- 当前快照下载成功且验证完成后才切换缓存。离线可用已验证本机缓存继续手选计算，并显示必要的离线状态；无缓存则明确不可计算，不能展示假数据。
- OCR需要网络及可用服务；断网时手选计算继续可用。后台返回重查任务和当前目录版本，不自动重复上传。
- 相册只在用户主动选择一张截图后上传；不扫描相册、不自动上传其他照片，不永久复制原图。此为用途和访问设计，不把上传组件当图片内容安全审核。

## 隐私/UGC及平台准备

遵循现有兼容性文档新增的待落实要求：首版仍有私有识图图片输入，不能因去掉投稿/昵称/反馈就声称完全没有用户图片。应列明用途、谁能访问、保留/删除、是否外送及失败处理，并按微信后台实际要求核对声明。OCR、MIME检查和私有存储都不等于内容安全检测。

当前未接入微信内容安全API，不将其写成已实施。体验分发前明确并落实首版图片安全处理策略；选择外部审核服务及其数据传送须另行确认，本次不开户、不调用、不上传图片到第三方。若接入所选接口需要平台身份，只使用访客验证中服务端实际取得并按用途管理的身份；不能伪造OpenID或把浏览器游客令牌当平台身份。此项不等于已经完成用户账号绑定。

实施前需核实小程序AppID/主体与体验成员权限、服务域名/TLS、上传/请求域名、隐私声明和真机测试设备。这里只列项目准备项，不代表平台资质或审核已通过；后台操作与发布由用户协调。

## 里程碑与可复现验收

### A：共享核心与手选闭环

先抽取候选组装/规则派生，保留网页入口；建立同一已批准数据快照、地图顺序、车库/星级/OC及档位输入的网页/共享模块对照。再做小程序主页面、分服本机草稿和结果展示。完成标准：同输入候选、方案顺序、每车时间/总成绩和空缺一致；国服四/五区、各档、缺成绩与国际OC场景覆盖；原网页回归通过。此阶段无识图也能完整使用。

### B：原生会话、快照和现有截图识别

在隔离状态实现匿名会话与原生上传适配、私有任务委托；前端接入选图/预览/五槽修正/确认。完成标准：有效截图实际经过同一worker，结果/顺序与网页一致；手改/取消不误覆盖，跨会话/跨服/过期/目录变化拒绝，超时/429可恢复，幂等不重复上传；相机拍屏不列为支持能力。单图上限、multipart余量、恶意字段、全局配额和隐私/图片处理策略完成验证。

### C：开发者工具与真机体验验收

用独立测试后端/数据，完成iOS和Android真机：首次进入、相册选取、选车改星、键盘/搜索、长列表、结果、返回、前后台切换、弱网/断网/缓存不足、耗时计算取消及重复点击。工具模拟不代替真机，后端单测不代替用户验收。体验版配置不得指向正式写回或带入正式账号库；若使用生产只读/识图服务，须另行授权、配额和现场核验，不自行切换。

最终交付：小程序源码提交、共享模块/数据来源、可复现构建配置及产物、接口协议、自动化/双真机/用户验收记录、隐私/UGC入口清单、域名与原生API配套变更、版本兼容及回退说明。用户确认后再单独授权上传体验版，不将“本地完成”写成“已发布体验版”。

## 上线后的开发方式

网页稳定版本保留；功能在独立分支/环境开发，共享核心变更同时跑网页与小程序对照，两个UI分别验收。后端兼容旧小程序客户端，优先新增能力、保留旧字段/语义并按能力开关启用，避免一次后端升级要求所有客户端立刻更新。账号/正式成绩结构变更先列兼容影响，再按相应职责授权实施。

每轮源码、数据、模型和小程序构建来源分开固定；功能开发、本地测试、用户验收、平台体验上传/审核及生产部署分别记录。不为实现小程序复制正式账号/成绩、不同步工作簿、不擅自向其他对话派工。后续英文/国际实图/拍照可沿用同一OCR结果协议，但分别做样本与准确率验收。
