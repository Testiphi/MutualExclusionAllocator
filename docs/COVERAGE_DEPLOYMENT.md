# 成绩覆盖表与贡献解锁：已有站点升级

本轮用户授权先将Demo完成为真实功能，再分组提交推送与构包。应用源码和数据来源分别固定，具体提交、包SHA和发布ID以最终RELEASE.json/完成回执为准。开发对话不操作生产，不发公告、不清理、不创建监控。

## 行为与范围

- Excel式网格从正式运行数据只读生成，不读取或导出Excel。已填显示星号，空白可投稿；有效车池和星级由现有目录决定，不生成无效空格。每组48个车辆列，可搜索和翻页；高手每车一列，表头下拉切换合法星级。按当前服别/分区/档位/跑法的实际记录覆盖地图数降序，同分按车名，切换星级不会重排。
- 按服别/分区/档位/跑法，从全表默认满星实际记录中挑选互补车辆列：每次优先补足最多尚无参考的地图行，同分按覆盖数和车名稳定选择，直到覆盖所有本来有记录的行。参考列排在前面，余车仍按覆盖数排序。仅开放这些列的非OC实际成绩，不再公开整张小地图行，不另设参考行或按钮。选择在搜索、地图筛选、翻页和个别星级切换前固定；切换星级只看同车对应记录，不改参考车辆、不补估算。实际数据版本变化时重新计算。当前普通跑法国服五区理论3列/高手7列、四区理论5列/高手9列；国际五区理论3列。国服四区高手原本2行全车满星缺记录，仍留空，不为参考而造值。
- A方案限制表格展示，首页现有公开JSON/快照和计算保持；不宣传为底层数据保密。国际服仅五区满星理论覆盖与公开参考，不开放投稿或国服积分解锁。
- 国服投稿复用现有投稿页与草稿、证据、审核、贡献、发布和回滚流程。鼠标单击空格直达预填页；触屏轻点选中、格旁浮现“再点一次填写”，再次点同格进入，移动超过10像素、取消手势或滚表清除选择，不设底部操作按钮。游客经主页登录后直达预填页。目标默认折叠，只需填写成绩；说明/视频/图片可选，批量/暂存折叠保留。可选图片按原接口上传后自动提交审核。失败后保留草稿和提交标识，重试不重复创建或重复上传已成功图片。待审不计为已填、不自动加分。
- 权益规则v1：质量>=6的独立目标为有效贡献、>=8为高质量；沿用既有总积分，不消费。一级积分>=50且有效>=5可选1张国服大地图；二级积分>=150、有效>=15、高质量>=5开放全部国服。管理账号工作权限独立于贡献等级，可看全部国服。历史已计入账本的有效贡献参与，未纳入贡献账本的旧投稿不补分。
- 一级选图不可自行更换，改分/重开/回滚后动态重算权益，暂不达标时保留选择但收回显示。恢复达标后复用原选择，不删审计。地图ID由cn+大地图名称的稳定摘要组成，不改现有地图映射；后续改名需单独核对选图兼容，不自动跨图转换。

## 运行状态保护

新增accounts.sqlite3附属三表：coverage_schema(1)、coverage_choices、coverage_events。原账号、成绩、车库、投稿、反馈和贡献行保持。没有覆盖表独立数据库、没有新依赖或系统服务。普通本地库必须显式--coverage且contributions/score-version-lab同时启用；生产只读取已迁移状态，不在启动时建新表。

所有国服读取来自当前正式score-state，与应用包基线分离。包内4458键不能覆盖生产成绩；国服新车辆规则也不能靠覆盖代码JSON激活，仍须数据维护/运维协调正式成绩差异。国际661条三件套为独立运行投影；700完整维护、四区/高手、36参考及工作簿不入包。严禁导入本地演示账号、数据库、评分或投稿。

## 云端执行顺序（逐步核对输出后继续）

1. 先只读确认current/PID实际cwd、health及各schema、正式国服score版本、pending_batches、磁盘、备份timer和最近真实备份/恢复情况。历史171d872a只是历史证据。
2. 校验完整外层SHA及交付目录SHA清单；用本包新deploy_production.py仅暂存。进入新版本，核对Python3.12/x86_64，执行production/install-runtime.sh离线锁定安装与Linux原生临时库自检。新自检覆盖coverage迁移、锁、幂等及成套恢复，不能以Windows测试替代。
3. 从新版本工具做在线成套备份、verify-backup和独立restore-drill。确认维护窗口，暂停原备份timer，确认备份服务结束，停应用并核对MainPID为0；再做停服最终成套备份/校验/演练。
4. 使用既有config、服务用户及新版本.venv，从新版本目录执行只读preflight：

```text
.venv/bin/python -B -m backend.coverage_production preflight --config /etc/racepick/production.json
```

要求原组件、贡献schema1、正式score版本和未完成批次符合现场核验。按同一现场国服版本执行：

```text
.venv/bin/python -B -m backend.coverage_production migrate --config /etc/racepick/production.json --expected-version <现场正式国服成绩版本>
```

仅当现场coverage_schema为0且前置齐全时执行本组件首次迁移。若现场已是完整coverage_schema1，本次仅升级应用，不重复迁移，保留原选图和事件内容，检查前后逐表数量/内容一致。任何部分表或其他schema异常即停止。

首次迁移工具先成套备份、获取服务/成绩锁，并逐表指纹保持旧业务行；新选择与事件表为空，不导入测试权限，不重跑旧账号/成绩/贡献/反馈/通知/统计迁移。检查existing_rows_preserved、coverage_schema1及原score版本不变，再做含coverage声明的成套备份和独立恢复演练。已有schema1的升级也必须做含既有选图/事件的成套备份及独立恢复验证。

5. 本轮没有新增Nginx、SMTP、环境变量或systemd要求。保留现有统计独立桶和业务限流，先核对现场实际配置；覆盖表GET及只读POST /api/coverage/view、选图POST及投稿沿用Origin/CSRF与业务保护，不为页面擅自放宽限流。
6. 用新工具通过兼容检查后激活、启动，核对current/PIDcwd/health覆盖表schema1、原组件和score版本保持。核对游客免费样本、登录回跳与预填、待审不占格、账户隔离、一级选图和动态权益、二级国服/国际仅浏览、旧投稿及原功能。真实投稿由用户决定，不伪造生产成绩/积分或刷生产流量。
7. 复核部署后成套备份/演练；恢复原timer，核验一次真实新组件备份结果和下一次计划。记录实际路径、SHA、版本及验收，不把未来计划写成成功。手机微信由用户实际验收。

## 停止与回退

版本漂移、未完成批次、备份/演练/权限/兼容/关键页面异常即停止并保留现场。三表启用后，旧版本不能记录和检查这些权限，不得只切旧链接或用旧部署工具绕过门禁。优先保留数据修复或切兼容版本；如需恢复整套业务状态，先保存升级后新增、演练并取得明确数据恢复授权。不得单库恢复、删除新表或用包内JSON覆盖score-state。
